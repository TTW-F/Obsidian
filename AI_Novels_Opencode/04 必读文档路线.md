# 04 必读文档路线

> [!tip] 文档路径里的 `packages/...`、`docs/...` 等是仓库内相对路径；看不懂 git/仓库概念先读 [[09 名词解释#git 仓库 / repo]]。

> [!warning] 不要跳
> 顺序即依赖关系。没读前一篇就跳后一篇，会看不懂"为什么这么设计"。

## 阅读顺序

1. **`CONTEXT.md`**（仓库根）
   领域词汇表 + 设计纪律 + 严厉禁止清单（补丁叠补丁 / 平行实现 / 自造轮子 / 权宜方案永久化）。先建立 ubiquitous language。

2. **`.scratch/opencode-novel-saas/spec.md`**（仓库内）
   **产品语义权威**。做了哪些决策、为什么复用 OpenCode 而非自建、六角色/多 Agent 运行时"不锁死"的取舍、平台面扩展 console 的边界。

3. **`docs/novel/README.md`**（仓库内，很短）
   文档导航门，告诉你每篇文档该什么时候读。

4. **`docs/novel/architecture-boundaries.md`**（仓库内）
   A→B→C 三代叠层、**机器拓扑**（开发机=Windows 唯一真相源；`192.168.31.35` Ubuntu 只验收不改代码）。

5. **`docs/novel/target-architecture.md`**（仓库内，~100KB）
   **改状态/加机制前必读**。行业范式对照、代码地图、三条主链路端到端走读（发消息/重连/Keep）、8 条不变量（各配真实判例）、崩溃恢复与并发准入、新需求落地正/反例、四阶段路线图。

6. **`docs/novel/01-frontend-api-contract.md`**（仓库内）
   前端契约矩阵（不可变权威）。路径/字段/枚举/409/Idempotency/SSE 帧格式。

## 辅助文档（按需）
- `docs/novel/adr/` — 用户模型控制平面等 ADR。
- `docs/novel/PERF.md` / `QUALITY.md` — 性能与质量基线。
- `.scratch/opencode-novel-saas/issues/*.md` — 22 张需求票，是拆解任务的颗粒度。

→ 读完后用 [[05 代码入口走读]] 对照源码，按 [[06 实习学习路线]] 动手。
