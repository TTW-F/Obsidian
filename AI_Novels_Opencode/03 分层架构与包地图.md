# 03 分层架构与包地图

> [!abstract] 先分清"底座（复用，别改内部）"和"我们写的（领域层）"
> monorepo 里 90% 是 OpenCode 原码；你主要打交道的是 `novel-core` / `novel-server` / `novel-web`。

## 包地图

| 层 | 路径 | 角色 | 要不要改 |
|---|---|---|---|
| 底座引擎 | `packages/core` `server` `protocol` `llm` `tui` `ui` `web` `cli` `console` `sdk` `sdk-next` `schema` `plugin` `identity` `enterprise` `stats` | OpenCode 成熟能力 | 一般**只复用**，不改动内部 |
| **领域·核心** | `packages/novel-core` | 作品 git 存储、唯一提交服务、检索索引、角色权限、目录骨架 | ✅ 主战场 |
| **领域·服务** | `packages/novel-server` | Workbench HTTP API、Session 桥接、SSE 事件、命令总线 | ✅ 主战场 |
| **前端** | `apps/novel-web` | Next.js 三栏工作室（章节树/编辑器/对话栏） | ✅ 主战场 |

## 领域层内部依赖方向

> [!note] 方向约束（来自 AGENTS.md）
> `Schema → Core → Protocol → Server`；Client 运行时可依赖 Schema/Protocol，**绝不**依赖 Core/Server；`sdk-next` 组合 Client+Core+Server。

## 运行时数据目录（不是源码！）
根目录这些**别碰、别读、别提交**：
- `.runtime-data-*`、`work-records/`、`works/`、`authors/`、`agent-store/`、`opencode.sqlite`、`command-idempotency.sqlite`、`author-sessions.json`
- 它们是运行态状态；改代码不会动它们，调试时别和源码混淆。

## 关键源码落点（详见 [[05 代码入口走读]]）
- 桥接核心：`packages/novel-server/src/runtime/opencode/`（adapter / event-mapper / sse-hub / delegation-flow）
- 唯一提交服务：`packages/novel-core/src/git/commit-service.ts`
- 六角色：`packages/novel-core/src/role.ts` + `work/role-permissions.ts`
