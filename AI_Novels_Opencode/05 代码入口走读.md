# 05 代码入口走读

> [!abstract] 从哪读起
> 后端从 `novel-server` 的 HTTP 边界入手，沿桥接进 OpenCode；核心存储/检索在 `novel-core`；前端是 `novel-web` 的各种 projection。

## 领域层·服务（先读边界，再读桥接）

| 文件 | 作用 |
|---|---|
| `packages/novel-server/src/main.ts` | 进程入口 |
| `packages/novel-server/src/app.ts` | HTTP app 装配 |
| `packages/novel-server/src/workbench.ts` | **Workbench HTTP API 总边界** |
| `packages/novel-server/src/workbench-events.ts` | 事件定义 |
| `packages/novel-server/src/sse-frame.ts` | SSE 帧格式 |
| `packages/novel-server/src/command-idempotency.ts` | 命令幂等（契约要求） |

### 桥接核心（最关键）`packages/novel-server/src/runtime/opencode/`
- `adapter.ts` — 进程内嵌入 sdk-next（不另起 serve 进程）
- `event-mapper.ts` — OpenCode Event V2 → public SSE 形状
- `sse-hub.ts` — SSE 分发
- `delegation-flow.ts` — 主管↔专家委派编排
- `startup-reconciliation.ts` — 启动恢复对账

## 领域层·核心 `packages/novel-core/src/`
| 文件 | 作用 |
|---|---|
| `git/commit-service.ts` | **唯一提交服务**：所有写路径收敛入口 |
| `git/work-repository.ts` | 作品 git 存储（建仓/写=diff/Keep/Undo） |
| `search/search-index.ts` | 检索索引（写后可见/Keep 不变/Undo 消失） |
| `role.ts` | 六角色常量 |
| `work/role-permissions.ts` | 目录写限域（设定→`设定/**` 等） |
| `work-layout.ts` | 作品目录骨架模板 |

## 前端 `apps/novel-web/src/`
- `app/` — Next.js 路由与布局
- `lib/*-projection.ts` — 大量 "projection" 文件 = UI 对 Agent 信息的**投影**（不是普通 chat 记录），如 `right-rail-eleven-zone-projection.ts`、`three-pane-linkage-projection.ts`
- `design-system/` — 组件与 tokens

## 建议阅读次序
1. `workbench.ts` 看 API 形状 → 2. `runtime/opencode/adapter.ts` 看引擎怎么嵌进来 → 3. `event-mapper.ts` 看事件怎么变 → 4. `novel-core/git/commit-service.ts` 看写路径收敛 → 5. `role.ts` + `role-permissions.ts` 看六角色边界。

→ 配合 [[03 分层架构与包地图]] 一起看。
